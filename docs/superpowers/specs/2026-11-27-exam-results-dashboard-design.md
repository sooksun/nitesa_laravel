# ผลการทดสอบระดับชาติ (RT / NT / O-NET) — เอกสารออกแบบ

วันที่: 27 พ.ย. 2569
สถานะ: รออนุมัติ

## เจตนา

สพป.สกลนคร เขต 1 ต้องการเห็นผลการทดสอบระดับชาติปีการศึกษา 2568 ของโรงเรียนในสังกัดบนระบบ NITESA และให้ผลสอบแต่ละรายการผูกกับโรงเรียนในระบบ เพื่อให้ผู้บริหาร ศึกษานิเทศก์ และโรงเรียนใช้ประกอบการนิเทศ ติดตาม และประเมินผล

## เป้าหมาย

1. เก็บผลสอบ 4 ชุดของปี 2568 ลงฐานข้อมูล ผูกกับตาราง `school`
2. มีหน้า dashboard แสดงภาพรวม เปรียบเทียบ และตารางรายโรงเรียน
3. หน้ารายละเอียดโรงเรียนแสดงผลสอบของโรงเรียนนั้น
4. ADMIN อัปโหลดไฟล์ปีถัดไปเองได้จากหน้า "นำเข้าข้อมูล" และมีคำสั่ง artisan ที่ใช้ตัวอ่านไฟล์ชุดเดียวกัน
5. ใช้ไฟล์ RT เป็นรายชื่อโรงเรียนจริง 174 แห่งของระบบ (ผู้ใช้ตัดสินใจแล้ว)

## สิ่งที่ไม่ทำ

- ผลสอบรายนักเรียน
- กราฟแนวโน้มข้ามปี (มีข้อมูลปีเดียว โครงสร้างรองรับหลายปีไว้แล้ว)
- แก้ไขคะแนนด้วยมือผ่านหน้าจอ
- API endpoint และการ export Excel ของหน้านี้
- ลบหรือแก้โรงเรียนทดสอบ 50 แห่งที่มีอยู่ในฐานข้อมูลเครื่องพัฒนา

## สิ่งที่ถือว่าล้มเหลวแม้ทำงานได้

- ผลสอบไปผูกผิดโรงเรียน: ถ้าจับคู่ไม่ได้แน่ชัด ต้องไม่นำเข้าแถวนั้นและรายงานให้ ADMIN เห็น ห้ามเดา
- ผู้ใช้ SUPERVISOR/SCHOOL เห็นผลสอบของโรงเรียนนอกขอบเขตตนเอง
- นำเข้าซ้ำแล้วได้แถวซ้ำ

- ไฟล์ NT มี sheet ที่สองเป็นเกณฑ์ระดับคุณภาพ และหมายเหตุว่าคะแนนอาจเป็น `*` หรือ `x` — ค่าที่ไม่ใช่ตัวเลขให้เก็บเป็น null
- ท้ายไฟล์ RT มี 4 แถวค่าเปรียบเทียบ: "ระดับเขตพื้นที่" (ผู้เข้าสอบ 2965, เฉลี่ย 80.2), "ระดับจังหวัดสกลนคร", "ระดับสังกัด(สพฐ.)", "ระดับประเทศ" แล้วตามด้วยแถวว่างจนถึงแถว 1000
- ไฟล์ NT ไม่มีแถวค่าเปรียบเทียบ

## ทางเลือกที่พิจารณา

**การเก็บข้อมูล**

- ก. ตารางเดียว หนึ่งแถวต่อโรงเรียน × ชนิดสอบ × ปี คอลัมน์คะแนนคงที่ — **เลือก** เพราะ query เฉลี่ยรายอำเภอ/รายวิชาได้ตรง ๆ และรูปแบบการสอบทั้ง 4 ชุดนิ่ง
- ข. หนึ่งแถวต่อวิชา — ยืดหยุ่นกว่าแต่ต้อง pivot ทุกครั้งที่แสดงตาราง
- ค. แยกตารางต่อชนิดสอบ — ตารางเกือบซ้ำกัน dashboard ต้องเขียนแยก

**การนำเข้า**

- ก. คำสั่ง artisan อย่างเดียว — ปีถัดไปต้องมีคนเข้า server
- ข. artisan + อัปโหลดผ่านหน้านำเข้าของ ADMIN — **เลือก** เพราะ ADMIN ทำเองได้ทุกปี

ผู้ใช้เลือก 1ก + 2ข ในการสนทนา

## การออกแบบ

### ตาราง `examresult`

ตามแบบแผนของ repo: ชื่อตารางตัวเล็กเอกพจน์, id เป็น ULID 26 ตัว, คอลัมน์ camelCase, `createdAt`/`updatedAt`

| คอลัมน์ | ชนิด | หมายเหตุ |

Model `App\Models\ExamResult` + ความสัมพันธ์ `School::examResults()`

### ระดับคุณภาพและค่าเปรียบเทียบ

- RT: ใช้ระดับผลจากไฟล์
- NT: คำนวณจากเฉลี่ย 2 ด้านตามเกณฑ์ใน sheet ที่สองของไฟล์ — ≥68.5 ดีมาก, ≥47 ดี, ≥27.5 พอใช้, ต่ำกว่านั้น ปรับปรุง เก็บเกณฑ์ไว้เป็นค่าคงที่ในโค้ด (การตัดสินใจของผู้ออกแบบ)
- O-NET: ไม่มีระดับคุณภาพ
- O-NET และ RT: แถวค่าเปรียบเทียบท้ายไฟล์เก็บเป็นแถว scope `AREA` / `PROVINCE` (RT เท่านั้น) / `OBEC` / `NATIONAL` และ dashboard ใช้ค่าทางการเหล่านี้ในการเทียบ
- NT: ไฟล์ไม่มีค่าเปรียบเทียบ ให้ dashboard คำนวณค่าเฉลี่ยเขตจากแถวโรงเรียนโดย**ถ่วงน้ำหนักด้วยจำนวนผู้เข้าสอบ** และกำกับบนหน้าจอว่า "คำนวณจากข้อมูลโรงเรียน" ไม่มีการเทียบ สพฐ./ประเทศ (การตัดสินใจของผู้ออกแบบ)
- ค่าเฉลี่ยของกลุ่มโรงเรียนในขอบเขต/รายอำเภอ: RT, NT ถ่วงน้ำหนักด้วยผู้เข้าสอบ; O-NET ไม่มีจำนวนผู้เข้าสอบ ใช้ค่าเฉลี่ยธรรมดาของโรงเรียนและกำกับว่า "เฉลี่ยรายโรงเรียน" (การตัดสินใจของผู้ออกแบบ)

### การจับคู่โรงเรียน

เครื่องจริงมีโรงเรียนจริงอยู่ในตาราง `school` แล้ว (ผู้ใช้ยืนยัน) โดยไม่ทราบว่าใช้รหัสชุดใด และมีประวัติการนิเทศกับการมอบหมายศึกษานิเทศก์ผูกอยู่ ดังนั้นการจับคู่ต้องทำงานได้ไม่ว่ารหัสเดิมเป็นชุดไหน และต้องไม่สร้างโรงเรียนซ้ำ

ลำดับการจับคู่ของทุกแถว ทุกชนิดสอบ:

1. รหัสในไฟล์ (ถ้ามี) ตรงกับ `school.code`
2. ชื่อที่ normalize แล้ว (ตัดช่องว่าง, เครื่องหมายคำพูด, วงเล็บ, จุด, คำว่า "โรงเรียน") ตรงกับ `school.name` ที่ normalize แบบเดียวกัน ถ้าไฟล์มีอำเภอ (RT, NT) และโรงเรียนในระบบมีอำเภอ ต้องตรงกันด้วย
3. ตาราง alias ใน `config/exam.php` (ชื่อในไฟล์ที่ normalize แล้ว → ชื่อโรงเรียนในระบบที่ normalize แล้ว)
4. เจอมากกว่าหนึ่งหรือไม่เจอ: ไม่นำเข้าแถวนั้น ใส่ในรายการ "จับคู่ไม่ได้" ห้ามเดา

### รายชื่อโรงเรียนจากไฟล์ RT

เมื่อเลือก "เพิ่มโรงเรียนที่ยังไม่มีจากไฟล์นี้" ตอนนำเข้า RT:

- แถวที่จับคู่กับโรงเรียนเดิมได้ (ตามลำดับข้างบน): ใช้โรงเรียนเดิม **ไม่แก้ `code` และ `name`** เติม `district` เฉพาะเมื่อของเดิมว่าง
- แถวที่จับคู่ไม่ได้เลย: สร้างโรงเรียนใหม่ด้วยรหัส RT, ชื่อตามไฟล์ (ไม่เติม "โรงเรียน"), อำเภอตามไฟล์, `province` = `สกลนคร`
- แถวที่กำกวม (เจอมากกว่าหนึ่ง): ไม่สร้าง ไม่นำเข้า รายงาน
- ไม่ลบโรงเรียนใด

### โหมดตรวจก่อนนำเข้า (dry run)

เพราะตรวจกับข้อมูลเครื่องจริงจากเครื่องพัฒนาไม่ได้ ตัวนำเข้าต้องมีโหมดที่อ่านไฟล์และจับคู่ครบทุกขั้น แต่ไม่เขียนฐานข้อมูล แล้วรายงาน: จับคู่ได้กี่แถว (ด้วยรหัส/ชื่อ/alias อย่างละเท่าไร), โรงเรียนที่จะถูกสร้างใหม่ (รายชื่อ), แถวที่จับคู่ไม่ได้หรือกำกวม (รายชื่อ) หน้าอัปโหลดมีปุ่ม "ตรวจสอบก่อนนำเข้า" คู่กับปุ่ม "นำเข้า" และคำสั่ง artisan มี `--dry-run`

ชื่อที่ทราบแล้วว่า normalize แล้วยังไม่ตรงกับ RT (ผู้สร้างต้องเปิดไฟล์ RT หาคู่ที่ถูกสำหรับเครื่องพัฒนา แล้วใส่ alias เฉพาะรายที่มั่นใจ รายที่ไม่มั่นใจให้ปล่อยเป็น "จับคู่ไม่ได้" และรายงานผู้ใช้):

- NT: `บ้านท่าม่วงทุ่งมั่งสามััคคีวิทยา` (เมืองสกลนคร), `บ้านยางโล้นเจริญราษฎรไพบูลย์` (ภูพาน), `บัานสะพานสาม` (ภูพาน)
- O-NET ป.6: `บ้านนา (คุรุราษฎรอุทิศวิทยายน)`, `บ้านโพนแพง เจียรวรนนท์อุทิศ 5`, `บ้านยางโล้นเจริญราษฎรไพบูลย์`, `ไทยรัฐวิทยา 110 (บ้านชมภูพาน)`
- O-NET ม.3: `บ้านโพนแพง เจียรวรนนท์อุทิศ 5`, `บ้านยางโล้นเจริญราษฎรไพบูลย์`

### ตัวนำเข้า

`App\Services\ExamResultImporter` — รับ (ชนิดสอบ, path ไฟล์, ปีการศึกษา, ตัวเลือก syncSchools) คืนผลสรุป: จำนวนแถวที่อ่าน, นำเข้า, จับคู่ไม่ได้ (พร้อมเลขแถวและชื่อ), โรงเรียนที่สร้าง/อัปเดต

- อ่านไฟล์ด้วย `maatwebsite/excel` (`Excel::toArray`) เหมือนหน้านำเข้าเดิม ใช้ sheet แรก
- หาแถวหัวตารางโดยมองหาช่อง "ชื่อโรงเรียน" แล้วตรวจว่าหัวคอลัมน์ตรงกับชนิดสอบที่เลือก ถ้าไม่ตรงให้ปฏิเสธทั้งไฟล์พร้อมข้อความบอกเหตุ (กันอัปโหลดผิดชนิด)
- ทั้งการนำเข้าอยู่ใน `DB::transaction`
- นำเข้าซ้ำ = อัปเดตแถวเดิม (idempotent)

ทางเข้า 2 ทาง ใช้ service เดียวกัน:

1. `php artisan exam:import {type} {file} {--year=} {--sync-schools} {--dry-run}` — `type` คือ `rt|nt|onet-p6|onet-m3`
2. หน้า `App\Livewire\Import\ImportIndex` (ADMIN เท่านั้นตาม route เดิม): เพิ่มชนิดนำเข้า 4 ชนิด, ช่องปีการศึกษา (ค่าเริ่มต้น = ปี พ.ศ. ปัจจุบันลบ 1), ช่องติ๊ก "เพิ่มโรงเรียนที่ยังไม่มีจากไฟล์นี้" (แสดงเฉพาะ RT), ปุ่ม "ตรวจสอบก่อนนำเข้า" และแสดงรายการแถวที่จับคู่ไม่ได้ในกล่องข้อผิดพลาดเดิม

### หน้ารายละเอียดโรงเรียน

`SchoolShow` เพิ่มส่วน "ผลการทดสอบระดับชาติ": ตารางเล็กของปีล่าสุดที่มีข้อมูล หนึ่งแถวต่อชนิดสอบที่โรงเรียนมีผล แสดงคะแนนรายวิชา เฉลี่ย ระดับ และส่วนต่างจากค่าเฉลี่ยเขต ไม่มีผลสอบก็ไม่แสดงส่วนนี้

## ข้อจำกัด

- Laravel 10, PHP 8.1+, Livewire 3 — ทำตามแบบแผนใน `CLAUDE.md` ของ repo
- UI และข้อความเป็นภาษาไทย ปีแสดงเป็น พ.ศ.
- PHPUnit รันกับฐานข้อมูลตาม `.env` (ไม่มีฐานทดสอบแยก) ดังนั้น test อัตโนมัติให้ครอบคลุมเฉพาะส่วนที่ไม่เขียนฐานข้อมูล: ตัวอ่าน/แยกแถวของแต่ละชนิดไฟล์, การ normalize ชื่อ, การคำนวณระดับคุณภาพ NT ใช้ไฟล์ตัวอย่างขนาดเล็กที่สร้างใน test เอง เพราะ `doc/` ถูก gitignore
- ไฟล์ใน `doc/` ไม่ commit
- เข้าถึงฐานข้อมูลเครื่องจริงจากที่นี่ไม่ได้ การนำเข้าบนเครื่องจริงเป็นขั้นตอนของผู้ใช้: รัน dry run ก่อน ตรวจรายชื่อ "จะสร้างใหม่" ว่าไม่มีโรงเรียนที่มีอยู่แล้ว แล้วจึงนำเข้าจริง

## การตรวจรับ

1. รันนำเข้าทั้ง 4 ไฟล์บนเครื่องพัฒนา (RT ก่อน พร้อม sync โรงเรียน): sync สร้างโรงเรียน 174 แห่ง (รวมโรงเรียนทดสอบเดิม 50 เป็น 224), RT 174 แถว, NT/O-NET ตามจำนวนในไฟล์ลบด้วยรายการที่จับคู่ไม่ได้ซึ่งต้องรายงานเป็นรายชื่อ
2. รันซ้ำแล้วจำนวนแถวไม่เพิ่ม
3. ค่าเฉลี่ย O-NET ระดับเขตบนหน้าจอตรงกับไฟล์ (ป.6 เฉลี่ยรวม 33.39)
4. เปิดหน้า dashboard และหน้าโรงเรียนในเบราว์เซอร์ด้วยผู้ใช้ ADMIN และผู้ใช้ SUPERVISOR แล้วเห็นขอบเขตข้อมูลถูกต้อง — บนเครื่องพัฒนา ผู้ใช้ SUPERVISOR ทุกคนผูกกับโรงเรียนทดสอบซึ่งไม่มีผลสอบ ให้ผูกผู้ใช้ทดสอบหนึ่งคนกับโรงเรียนจริง 2–3 แห่งในฐานข้อมูลเครื่องพัฒนาเพื่อการตรวจนี้ (ไม่ใส่ใน seeder)
5. dry run ไม่เปลี่ยนจำนวนแถวในตารางใดเลย และบนฐานข้อมูลที่มีโรงเรียนชื่อเดียวกันอยู่แล้วด้วยรหัสอื่น (จำลองด้วยการแก้รหัสโรงเรียน 2–3 แห่งในเครื่องพัฒนา) การนำเข้า RT ซ้ำไม่สร้างโรงเรียนซ้ำ
6. `composer lint` และ `php artisan test` ผ่าน

## สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ

- โครงสร้างภายในของ importer (แยก parser ต่อชนิดไฟล์อย่างไร)
- รายการ alias ที่มั่นใจ (ดูหัวข้อการจับคู่โรงเรียน)
